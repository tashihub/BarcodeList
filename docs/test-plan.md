# BarcodeList 実機テスト仕様書

作成日: 2026-07-20
対象: Play Store公開前の実機での動作確認

## 0. テスト環境

| 項目              | 内容                                                                                                                  |
| ----------------- | --------------------------------------------------------------------------------------------------------------------- |
| ビルド種別        | Releaseビルド(署名済みAPK/AAB。`signing/`のアップロード鍵で署名)                                                      |
| 対象デバイス      | できれば2台以上(異なるAndroidバージョン・画面サイズ)                                                                  |
| Androidバージョン | 最低でも `SupportedOSPlatformVersion`(23 / Android 6.0)機と、なるべく新しいバージョン機の2種類                        |
| ネットワーク      | Wi-Fi/モバイル回線それぞれ、および機内モード(オフライン)での確認も行う                                                |
| 言語設定          | 端末言語を日本語/英語それぞれに切り替えて確認(設定アプリ内の言語切替とは別に、本アプリの「設定」タブの言語切替も確認) |

### 事前準備

- [ ] Play Consoleの「内部テスト」トラックにテスター(自分のGoogleアカウント)を登録し、テスト参加リンクからインストールする(ストア審査前でも実機確認できる正規ルート)
- [ ] AdMobの「テストデバイス」に実機のGoogle広告IDを登録する(登録しないと、たとえ`forceTesting: true`のままでも自分のアカウントに実クリックとしてカウントされるリスクがあるため必須)
- [ ] 過去バージョンをアンインストールしてから新規インストールする回(初回起動確認用)と、旧バージョンからの上書きアップデートで確認する回の両方をやる
- [ ] カメラ権限は「初回起動時にリクエストされるか」を見るため、**インストール直後はまだ許可しない状態**で最初のテストを始める

---

## 1. 権限まわり

- [OK] **1-1** 初回起動後、スキャンタブを開く → カメラ権限のリクエストダイアログが表示される
- [OK] **1-2** 権限リクエストで「許可しない」を選ぶ → クラッシュせず、カメラが使えない旨が分かる状態になる(真っ黒画面のまま固まる、等がないか)
- [OK] **1-3** 端末の設定からアプリの権限を後から許可する → アプリに戻る → カメラが正常に起動する
- [OK] **1-4** 権限を「今回のみ許可」で許可した場合 → 通常通りスキャンできる

## 2. バーコード作成(作成タブ)

作成タブに一覧表示される全13形式について、正常系・異常系を確認する。

- [OK ] **2-1** QRコード: 正常系(`https://example.com`、日本語混じりの文字列 例: `テスト123`)→ 日本語を含む文字列でも**クラッシュしないこと**(過去にShift_JISエンコーディング未登録でクラッシュした実績あり、§9-1で重点確認)
- [ ] **2-2** Code128: 正常系(`ABC-123`)/ 異常系(全角文字・絵文字混じり)→ ASCII以外はエラーメッセージが出る
- [ ] **2-3** Code39: 正常系(`ABC123`)/ 異常系(小文字 `abc123`、許可外記号 `@#`)→ 小文字は自動で大文字化されるか、または許可外文字でエラーになる
- [ ] **2-4** EAN-13: 正常系(12桁の数字)/ 異常系(11桁/13桁、英字混じり)→ 12桁ちょうどでチェックデジットが自動付与され13桁になる。桁数不一致・数字以外はエラー
- [ ] **2-5** EAN-8: 正常系(7桁の数字)/ 異常系(6桁/8桁)→ 同上(7桁→8桁)
- [ ] **2-6** UPC-A: 正常系(11桁の数字)/ 異常系(10桁/12桁)→ 同上(11桁→12桁)
- [ ] **2-7** ITF: 正常系(偶数桁の数字 例: `123456`)/ 異常系(奇数桁、英字混じり)→ 奇数桁・数字以外でエラー
- [ ] **2-8** Codabar: 正常系(`A123456A`等許可文字のみ)/ 異常系(許可外文字)→ 許可外文字でエラー
- [ ] **2-9** Code93: 正常系(`ABC123`)/ 異常系(全角・絵文字)→ ASCII以外でエラー
- [ ] **2-10** DataMatrix: 正常系(短い文字列/長めの文字列)→ **プレビューが正方形で見切れずに表示される**(§9-2で重点確認)
- [ ] **2-11** PDF417: 正常系(長めの文字列、数百文字程度)→ プレビューが表示され、作成後の結果画面でも見切れない
- [ ] **2-12** Aztec: 正常系(短い文字列)→ プレビューが正方形で表示される
- [ ] **2-13** GS1-128: 正常系(AI(01)+GTIN、AI(17)+有効期限など複数AIを組み合わせ)/ 異常系(桁数不正なAI値)→ AIごとのバリデーションが効くこと。作成後、結果画面でAI内訳が正しく表示されること

各ケース共通の確認項目:

- [ ] 作成ボタン押下直後にクラッシュしないこと
- [ ] 結果画面に遷移し、正しいバーコード画像が表示されること
- [ ] 結果画面から任意のフォルダに保存できること(フォルダ未選択時はエラーメッセージが出る)
- [ ] 3回に1回、インタースティシャル広告が表示されること(§8参照)

**注意**: Code128・Code39・Codabar・Code93・ITF・PDF417(桁数上限がなく、プレビューが横長=画面幅に合わせて伸縮する形式)は、入力文字列が長すぎるとバー幅が細かくなりすぎ、画面表示の解像度やカメラの読み取り性能の限界でスキャンできなくなることがある。これはアプリの不具合ではなく物理的な制約のため、長い文字列でスキャンできなくてもバグとして報告しなくてよい(作成画面のヒント文にもその旨を記載済み)。
一方、QRコード・DataMatrix・Aztecは正方形の固定枠(260×260)でプレビューされる2次元マトリクス形式で、モジュール数は文字数の平方根程度でしか増えないため、同じ懸念は相対的に小さい(注意書きは付けていない)。桁数固定のEAN-13/EAN-8/UPC-Aは対象外。

## 3. バーコードスキャン(スキャンタブ)

- [ ] **3-1** §2で作成した各形式のバーコードをカメラで読み取る → 全形式が正しく検出される
- [ ] **3-2** URLを表すQRコード(例: `https://example.com`)を読み取る → 読み取り結果画面でリンクが青字・下線付きで表示され、タップするとブラウザが開く
- [ ] **3-3** GS1-128バーコードを読み取る → 「GS1」種別バッジが表示され、AI内訳が正しく分解表示される
- [ ] **3-4** 通常のバーコード(URL・GS1以外)を読み取る → 「通常」種別バッジが表示され、生データがそのまま表示される
- [ ] **3-5** 読み取り直後 → **読み取った内容が自動的に履歴(フォルダ未指定)へ保存されている**こと(履歴タブで確認)
- [ ] **3-6** 読み取り結果画面から任意のフォルダを選んで保存 → フォルダにも保存され、フォルダ詳細画面に表示される
- [ ] **3-7** 読み取り直後、3秒以内に連続してもう一度同じバーコードにカメラを向ける → 3秒間は再検出されない(連続重複登録の防止動作)
- [ ] **3-8** 暗い場所・ピントが合いにくい距離での読み取り → 検出できない場合でもクラッシュしないこと

## 4. 履歴タブ

- [ ] **4-1** 履歴一覧を開く → 作成・スキャンした履歴が新しい順に表示される(最大100件)
- [ ] **4-2** 履歴の項目をタップ → 対応する結果画面(通常/GS1)に遷移し、内容が正しく表示される
- [ ] **4-3** 履歴を1件スワイプ削除(またはメニューから削除) → その項目のみ削除される
- [ ] **4-4** 「すべて削除」を実行 → 確認ダイアログが出て、OKすると履歴が全件削除される(フォルダに保存済みのバーコードは消えないこと)
- [ ] **4-5** 履歴タブを3回開く → 3回目の表示でインタースティシャル広告が表示される(§8参照)

---

## 5. フォルダタブ

- [ ] **5-1** 新規フォルダを作成 → フォルダ名を入力するダイアログが出て、作成後一覧に追加される
- [ ] **5-2** フォルダをタップして開く → フォルダ詳細画面に遷移し、そのフォルダに保存したバーコードのみ表示される
- [ ] **5-3** フォルダ詳細画面を3回開く → 3回目でインタースティシャル広告が表示される
- [ ] **5-4** フォルダ詳細画面からバーコードをタップ → 結果画面に遷移する
- [ ] **5-5** フォルダを削除 → 確認の上、フォルダとその中身がまとめて削除される

## 6. 設定タブ

- [ ] **6-1** 言語を「日本語」→「English」に切り替える → 「再起動が必要です」のアラートが出る。アプリを再起動すると全画面が英語表示になる
- [ ] **6-2** 言語を「端末の設定に従う」に戻す → 再起動後、端末言語に応じた表示に戻る
- [ ] **6-3** 「プライバシーポリシー」をタップ → アプリ内にプライバシーポリシー本文(日本語/英語)が表示される
- [ ] **6-4** 公開済みの https://tashihub.github.io/BarcodeList/privacy-policy/ をブラウザで直接開く → アプリ内表示と同じ内容が問題なく表示される
- [ ] **6-5** 「広告を削除する」をタップ(内部テスト・ライセンステスター状態で) → Google Playの購入ダイアログが表示される。テスト購入が完了すると「購入完了」アラートが出て、ボタンが「広告は削除されています」表示に切り替わる
- [ ] **6-6** 広告削除購入後、作成/スキャン/履歴/フォルダの各操作を行う → インタースティシャル広告が一切表示されなくなること(§8-3参照)
- [ ] **6-7** アプリを一度アンインストールし、同じGoogleアカウントで再インストール後「購入を復元」をタップ → 購入情報が復元され、広告削除状態に戻る
- [ ] **6-8** (購入していない状態で)「購入を復元」をタップ → 「購入情報なし」のアラートが出る
- [ ] **6-9** 購入ダイアログを表示させ、途中でキャンセルする → エラー表示にならず、何も起きずに設定画面に戻る
- [ ] **6-10** アプリ情報のバージョン表示を確認 → `ApplicationDisplayVersion`と一致した値が表示される

**注意**: 6-5〜6-9は実際にPlay Consoleで`remove_ads`商品を登録し、かつ自分がライセンステスターに登録されている状態でないとテストできません(登録が済んでいなければこの項目は一旦スキップし、商品登録後に改めて実施してください)。

## 7. ローカライズ表示

- [ ] **7-1** 日本語表示ですべてのタブ・画面を一通り巡回する → 文字化け・未翻訳(英語のまま)の箇所がないこと
- [ ] **7-2** 英語表示(§6-1で切替)ですべてのタブ・画面を一通り巡回する → 同上。特に新しく追加したSettings/PrivacyPolicy周りの英訳漏れがないか重点確認
- [ ] **7-3** 長い文言(特にドイツ語的に長くなりがちな英語ボタン文言)がある画面 → ボタンからテキストがはみ出していないこと

## 8. 広告表示

- [ ] **8-1** 作成・スキャン・履歴表示・フォルダ詳細表示・保存、それぞれを3回ずつ行う → 3回目の操作の直後にインタースティシャル広告(全画面)が表示される。1回目・2回目では表示されない
- [ ] **8-2** 広告が表示された状態で戻る/閉じるボタンを押す → アプリがクラッシュせず元の画面に戻る
- [ ] **8-3** 広告削除purchase後(§6-5)、上記8-1を再度行う → 何回操作しても広告が一切表示されないこと
- [ ] **8-4** 機内モード(オフライン)で広告表示条件を満たす操作をする → 広告読み込みに失敗してもアプリの操作自体はブロックされず続行できること(エラーで固まらない)

## 9. 回帰テスト(過去に発生した不具合の再発防止)

### 9-1. QRコード作成時のクラッシュ(Shift_JISエンコーディング)

過去に、入力欄にフォーカスが残ったままQRコードの「作成」を押すと、特定の文字列(漢字を含むなど)でクラッシュする不具合があった。`System.Text.Encoding.CodePages`の登録漏れが原因で修正済みだが、念のため下記を確認する。

- [ ] **9-1-1** QRコード作成画面で、入力欄にカーソル(フォーカス)を置いたまま、日本語(漢字)を含む文字列を入力し、キーボードを閉じずに「作成」ボタンを押す → クラッシュしないこと
- [ ] **9-1-2** 「点滅」「漢字」「日本語テスト」など、複数の漢字を含む文字列で繰り返す → すべてクラッシュしないこと

### 9-2. DataMatrix作成時のプレビュー見切れ

- [ ] **9-2-1** DataMatrix形式でバーコードを作成し、結果画面のプレビューを確認する → 正方形の枠内に収まり、バーコードの端が切れていないこと
- [ ] **9-2-2** QRコード・Aztecでも同様に確認する → 同上(正方形プレビュー)
- [ ] **9-2-3** Code128やEAN-13など1次元バーコードのプレビューを確認する → 横長のプレビューで、こちらも見切れていないこと

### 9-3. 広告表示とスキャン/作成結果表示が重なった際のクラッシュ

過去に、インタースティシャル広告の読み込み完了(`LoadAndShow`)と結果画面への遷移(`Shell.Current.GoToAsync`)がほぼ同時に走ると、広告の全画面表示と画面遷移が競合してクラッシュする不具合があった。広告表示を画面遷移完了後に行うよう順序を修正済みだが、念のため下記を確認する。

- [ ] **9-3-1** インタースティシャル広告が表示される回(3回に1回、§8参照)を狙って、スキャンタブでバーコードを読み取る → 結果画面(ScannedDataView)への遷移後に広告が表示され、クラッシュしないこと
- [ ] **9-3-2** 同様に、作成タブで通常のバーコードを3回作成し、3回目の作成時 → 結果画面(BarcodeResultView)への遷移後に広告が表示され、クラッシュしないこと
- [ ] **9-3-3** 同様に、GS1-128を3回作成し、3回目の作成時 → 結果画面(Gs1128ResultView)への遷移後に広告が表示され、クラッシュしないこと
- [ ] **9-3-4** 上記9-3-1〜9-3-3を電波状況の悪い環境(広告読み込みが遅くなる状況)でも繰り返す → 広告読み込みが結果画面表示より遅れて完了しても、表示中・表示後にクラッシュしないこと

## 10. 非機能テスト

- [ ] **10-1** 端末をダークモードに切り替えてアプリを開く → 全画面が正しくダークカラーで表示され、文字が読めなくなる箇所がないこと
- [ ] **10-2** 画面回転(縦→横、横→縦) → レイアウト崩れやクラッシュがないこと(対応していない場合は回転自体をロックしているかも確認)
- [ ] **10-3** スキャン中にホームボタンでバックグラウンドへ → 再度アプリを開く → カメラが正常に再開する、またはクラッシュしない
- [ ] **10-4** バーコード作成中に他アプリの通知が来て一時的に離脱 → 戻る → 入力内容が保持されている、またはクラッシュしない
- [ ] **10-5** 低速回線・機内モードでアプリ全般を操作する → 広告以外の主要機能(作成・スキャン・履歴・フォルダ)はオフラインでも問題なく動作すること(すべてローカルDBのため)
- [ ] **10-6** ストレージ容量が少ない端末での動作(可能であれば) → 保存失敗時にクラッシュせず、エラーメッセージが出ること

## 11. リリースビルド固有の確認

- [ ] **11-1** 署名済みAPK(`com.tashihub.barcodelist-Signed.apk`)を実機に直接インストールして起動 → 正常に起動すること(Debugビルドとの差異がないか)
- [ ] **11-2** `ApplicationId`が`com.tashihub.barcodelist`になっていることを端末の「アプリ情報」で確認 → 一致していること
- [ ] **11-3** `forceTesting`/`debugMode`を`false`に切り替えた**最終リリース直前ビルド**でのみ実施: 実際の広告(テスト広告ではないもの)が表示されるか確認 → **この確認は絶対に自分で何度もタップ・クリックしないこと**(誤クリックはAdMobポリシー違反でアカウント停止リスクあり)。表示されることだけ目視確認したら速やかに他の操作に移る

## 不具合報告テンプレート

テスト中に問題を見つけたら、以下の形式で記録する。

```
### [重大度: 致命的/重大/軽微] 不具合タイトル

- 発生日時:
- 端末・Androidバージョン:
- 再現手順:
  1.
  2.
  3.
- 期待結果:
- 実際の結果:
- スクリーンショット/ログ(あれば):
```

Logcatで拾えるクラッシュログは `FileSystem.AppDataDirectory/applog.txt`(`AppLogger`が記録)にも保存されるため、実機からファイルを取り出せる場合は合わせて添付すると原因調査がしやすい。
